# SONORA v3.34.0 - Lavalink & Performance Improvements

**Release Date:** January 11, 2026

## Overview
Major stability improvements for Lavalink playback, performance optimizations for lyrics loading, and new track duration limit.

## Bot Updates

### Lavalink Improvements
- Fixed YouTube OAuth configuration for reliable playback
- Updated youtube-plugin to v1.16.0 with `TVHTML5EMBEDDED` client
- Disabled deprecated built-in YouTube source
- Fixed "Already connected to voice channel" error when playing next track
- Increased audio buffer for smoother playback (5s buffer, 20s frame buffer)
- Fixed wavelink track end `NoneType` error with null checks

### Performance Optimizations
- Lyrics loading now uses ThreadPoolExecutor (non-blocking)
- Increased lyrics fetch delay to 5 seconds for audio stability
- Progress bar no longer freezes during lyrics loading
- Audio stuttering significantly reduced

### Track Duration Limit
- Maximum track duration: **15 minutes** (900 seconds)
- Tracks exceeding limit are rejected with friendly error message
- Queue auto-skips tracks over the limit

### UI Improvements
- Loading lyrics indicator (`<a:loading3:...>`) now shows in all player paths
- Fixed missing loading emoji in main Lavalink playback path
- Fixed missing loading emoji in playlist handler

### Bug Fixes
- Fixed `'MetadataInfo' has no attribute 'stream_url'` in loop replay
- Fixed `Player.stop()` coroutine not awaited warning
- Fixed Developer Dashboard `/api/bot/developer/stats` 500 error
- Fixed `is_connected()` check for Lavalink Player compatibility

### Cache & Bandwidth
- Cache check (local + rclone) runs before streaming for both play and loop
- Loop mode prioritizes cached files over re-streaming

## Technical Details
- Lavalink buffer: `bufferDurationMs: 5000`, `frameBufferDurationMs: 20000`
- YouTube clients: `TVHTML5EMBEDDED`, `WEB`
- OAuth refresh token stored in `application.yml`
- `MAX_TRACK_DURATION = 900` in `config/constants.py`
